IBM Verify Directory: Seed

This page documents the YAML schema which can be used to configure a Verify Directory Seed container for version 10.0.1.

The Verify Directory Seed container is used for data migration and replication setup.

The value of each YAML key entry can be provided in the YAML file as either plain text, base-64 encoded text (prefix: 'B64:'), retrieved from an environment variable (prefix: '$'), loaded from a local file (prefix: '@'), retrieved from a Kubernetes secret (format: secret:{name}/{field}), or retrieved from a Kubernetes ConfigMap (format: configmap:{name}/{field}).

In addition to this, each of the YAML keys can also be provided as an environment variable, using a normalized value of the key name as the environment variable name.

ℹ️ Click on section headers below to expand and view configuration details.

Configuration

▼

general object

▼

The general configuration elements of the container.

⚙️ Properties
admin object
▼

The credential information of the server.

⚙️ Properties
pwd string required

The password of the user which can be used to authenticate to the server.

key-stash string

The contents of the key stash file (.ksf) which is used to protect data. This file should be provided if cryptographic synchronisation is required between different servers. The key stash can either be obtained from a software based directory server installation, or a new one can be generated by starting this image with the 'keystash' argument. For example: 'docker run --rm icr.io/isvd/verify-directory-seed:latest keystash'. Please note that this will send a base-64 encoded version of the key stash to the console of the container.

license object required
▼

License configuration for the seed container.

⚙️ Properties
key string required

The license key, required to run the container.

accept string required

Which license agreement has been accepted, either 'limited' or 'standard' or 'enterprise'.

Allowed values:
limited standard enterprise

seed object

▼

The configuration entries associated with the seed container operations.

⚙️ Properties
migrate object
▼

Configuration for migrating data from an existing instance into a containerized environment.

⚙️ Properties
suffixes array
▼

The suffixes to migrate from the existing instance.

📋 Array Items
Type: string

A suffix DN to migrate (e.g., 'o=sample', 'dc=ibm,dc=com').

Examples

▼
Example 1
general:
  license:
    key: insert-license-key-here
    accept: standard
  key-stash: insert-key-stash-here
  admin:
    pwd: passw0rd1
seed:
  migrate:
    suffixes:
    - o=sample
Example 2
general:
  license:
    key: insert-license-key-here
    accept: standard
