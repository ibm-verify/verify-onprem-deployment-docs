IBM Verify Directory: Virtual Directory

This page documents the YAML schema which can be used to configure a Verify Directory Virtual Directory container for version 10.0.1.

The value of each YAML key entry can be provided in the YAML file as either plain text, base-64 encoded text (prefix: 'B64:'), retrieved from an environment variable (prefix: '$'), loaded from a local file (prefix: '@'), retrieved from a Kubernetes secret (format: secret:{name}/{field}), or retrieved from a Kubernetes ConfigMap (format: configmap:{name}/{field}).

In addition to this, each of the YAML keys can also be provided as an environment variable, using a normalized value of the key name as the environment variable name.

ℹ️ Click on section headers below to expand and view configuration details.

Configuration

▼

general object #

▼

The general configuration elements of the container.

⚙️ Properties
admin object required #
▼

The credential information of the virtual directory.

⚙️ Properties
pwd string required

The password of the admin user.

users array #
▼

Additional administrative users for this virtual directory.

📋 Array Items
dn string required

The DN of the user.

pwd string required

The password of the user.

role string required

The role assigned to the user (e.g., 'Administrator').

audit object #
▼

The configuration entries associated with the auditing of operations.

⚙️ Properties
enabled boolean

Enable or disable the audit service.

Default: False
id string

The identifier of the virtual directory. If no identifier is specified the hostname of the container will be used as the identifier.

license object required #
▼

License configuration for the virtual directory.

⚙️ Properties
key string required

The license key, required to run the container. Note: Virtual Directory requires a standard or enterprise license.

accept string required

Which license agreement has been accepted, either 'standard' or 'enterprise'.

Allowed values:
standard enterprise
ports object #
▼

The ports on which the virtual directory will listen for requests.

⚙️ Properties
ldaps integer

The port on which the virtual directory will listen for LDAPS requests.

Default: 9636
ssl object #
▼

SSL configuration details for the virtual directory.

⚙️ Properties
cert-label string

The label that identifies the servers Personal Certificate in the key database file.

virtual-dir object #

▼

The configuration entries associated with the virtual directory.

⚙️ Properties
view object #
▼

Configuration for the virtual directory view.

⚙️ Properties
suffix string

The suffix for the view (e.g., 'o=view').

attr string

The attribute to use for the view (e.g., 'cn').

clusters array required #
▼

The backend clusters that the virtual directory will proxy to.

📋 Array Items
suffix string required

The suffix for this cluster (e.g., 'o=sample').

endpoint-suffix string required

The endpoint suffix for this cluster (e.g., 'o=sample').

servers array required #
▼

The backend servers in this cluster.

📋 Array Items
target string required

The LDAP URL of the backend server (e.g., 'ldap://directory.ibm.com:9389' or 'ldaps://directory.ibm.com:9636').

role string required

The role of the server (e.g., 'Any').

user object required #
▼

The credentials to use when connecting to the backend server.

⚙️ Properties
dn string required

The DN to use when binding to the backend server.

password string required

The password to use when binding to the backend server.

attr-mapping array required #
▼

The attribute mappings between the virtual directory and the backend server.

📋 Array Items
attr string required

The attribute name in the virtual directory.

endpoint-attr string required

The attribute name in the backend server.

class string required

The class of the attribute mapping (e.g., 'Normal').

keyfile object #

▼

The configuration elements associated with the SSL key file.

⚙️ Properties
keys array #
▼

Any private keys used by the virtual directory.

📋 Array Items
label string required

The label which will be associated with this key.

key string required

The PEM encoded private key and public certificate.

trusted-certificates array #
▼

Any certificates which should be trusted by the virtual directory, in PEM format.

📋 Array Items
Type: string

A certificate which is to be trusted by the virtual directory, in PEM format.

Examples

▼
Example 1
general:
  license:
    key: insert-standard-license-key-here
    accept: standard
  admin:
    pwd: passw0rd1
    users:
    - dn: o=sample
      pwd: passw0rd1
      role: Administrator
virtual-dir:
  clusters:
  - suffix: o=sample
    endpoint-suffix: o=sample
    servers:
    - target: ldap://directory.ibm.com:9389
      role: Any
      user:
        dn: cn=root
        password: passw0rd1
    attr-mapping:
    - attr: cn
      endpoint-attr: cn
      class: Normal
Example 2
general:
  id: test-virtualdir
  license:
    key: insert-standard-license-key-here
    accept: standard
  ports:
    ldaps: 9636
  admin:
    pwd: passw0rd1
    users:
    - dn: o=sample
      pwd: passw0rd1
      role: Administrator
  ssl:
    cert-label: my-server
  audit:
    enabled: true
virtual-dir:
  view:
    suffix: o=view
    attr: cn
  clusters:
  - suffix: o=sample
    endpoint-suffix: o=sample
    servers:
    - target: ldaps://directory.ibm.com:9636
      role: Any
      user:
        dn: cn=root
        password: passw0rd1
    attr-mapping:
    - attr: cn
      endpoint-attr: cn
      class: Normal
    - attr: sn
      endpoint-attr: sn
      class: Normal
    - attr: ou
      endpoint-attr: ou
      class: Normal
    - attr: description
      endpoint-attr: description
      class: Normal
    - attr: member
      endpoint-attr: member
      class: Normal
keyfile:
  keys:
  - label: my-server
    key: '@/var/isvd/config/liberty-server.pem'
  trusted-certificates:
  - '@/var/isvd/config/ca.crt'
